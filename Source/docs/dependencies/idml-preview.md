# IDML embedded preview

## Контракт

VO-VE не рендерит верстку IDML. Обработчик подтверждает ZIP-сигнатуру и точное уникальное
содержимое записи `mimetype` (`application/vnd.adobe.indesign-idml-package`), затем читает только
`META-INF/metadata.xml`. Существующий ограниченный XMP-парсер выбирает первый JPEG из `PageInfo`
или, при его отсутствии, из `Thumbnails`.

Порядок `mimetype` в ZIP и метод его сжатия намеренно не считаются идентичностью документа:
проверяются точный путь, уникальность и распакованное содержимое. Это совместимый, но не
канонически строгий режим. ZIP64, рендер spreads/stories/styles, шрифты, связанные изображения и
определение количества страниц не входят в поддержку. IDML без сохранённого XMP/JPEG возвращает
типизированное отсутствие превью.

## Границы

- не более 4096 записей центрального каталога и 8 MiB самого каталога;
- `metadata.xml`: до 8 MiB сжатых и до 8 MiB распакованных данных;
- MIME извлекается с отдельным пределом 256 байт;
- JPEG, Base64, XML-структура, CRC и декодированные пиксели используют существующие ограничения
  InDesign/CDR/raster worker;
- отдельного процесса, DLL, редактора или нового runtime-компонента нет;
- кэш имеет идентификатор `document.idml.embedded-preview`, версия 1.

## Проверка

Синтетический корпус покрывает PageInfo, fallback Thumbnails, отсутствие превью, неверный MIME,
дубли MIME/metadata, CRC, обрыв ZIP, неверный Base64 и независимые пределы сжатого/распакованного
metadata. Весь путь worker/protocol/cache проверен на Windows и Linux.

Открытый корпус взят из `dimelords/idmllib` на зафиксированной ревизии `01546af`: два документа с
превью успешно прошли холодный и тёплый путь (358 x 512; 65-100 ms холодный, около 6 ms из кэша),
один документ подтвердил корректное отсутствие preview metadata. Это проверенный малый корпус, а
не обещание совместимости со всеми экспортерами IDML.

Windows runtime после этапа: 23 файла / 54 515 786 байт, без новых DLL и ниже лимита 80 MiB.
